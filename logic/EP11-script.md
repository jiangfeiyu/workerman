# EP11｜汇报、复盘、查 Bug，用的是三种完全不同的推理（演绎 · 归纳 · 溯因）

> **本集学习目标**：分清逻辑学三大核心推理工具——**演绎（保真派活）**、**归纳（复盘提炼）**、**溯因（排查原因）**，在不同职场场景里用对武器。

---

## 一、 自己先学懂（1 分钟内核 + 职场自测）

### 核心概念
- **演绎推理（一般规则 ➔ 具体结论）**：只要规则对，结论 **100% 确定**（适合定标准、向下派活、法务合规判断）。
- **归纳推理（多个具体案例 ➔ 一般规律）**：从有限样本总结规律，结论是**概率性**的（适合写月度复盘、总结爆款方法论）。
- **溯因推理（异常结果 ➔ 最可能的解释）**：像侦探破案，从结果倒推原因（适合查线上 Bug、分析业绩下滑）。注意：找到“最可能原因”后，仍需验证排除其他假设！

### 随堂自测
> 线上支付突然报错，运维看了一眼报错日志说：“肯定是刚才升级的 Redis 挂了，回滚吧！”——这是哪种推理？有啥隐患？

**答案解析**：这是**溯因推理**（从结果“报错”倒推“最可能的原因”）。隐患在于：如果只凭直觉挑了第一个想到的原因就回滚，万一其实是上游支付网关超时，回滚 Redis 也救不回来——溯因之后必须**快速验证**！

## 二、 4 段式分镜与口播逐字稿

### 场景 1｜01 职场翻车现场（`SceneHook`）
- **运维**：支付报错了！刚才刚好改过缓存配置，肯定是缓存的问题，赶紧回滚！
- **架构师**：等会！先看一眼监控，上游第三方网关也在同一秒超时了！

**口播字幕**：
1. 同事查线上故障：看到报错，就断定“一定是刚才改的配置搞挂的”，
2. 结果忙着回滚半天，问题还在，因为根本是第三方网关挂了！
3. 为什么会误判？因为汇报、复盘、查故障，用的压根不是同一种推理！

### 场景 2｜02 图解三大推理分工（`SceneReasoning` `mode="three-inferences"`）
**口播字幕**：
1. 职场工具箱里有三把推理武器，分工完全不同。
2. 第一把叫“演绎”：从公司红线推导具体能不能做，百分百确定，适合定规则；
3. 第二把叫“归纳”：从几十个复盘案例里提炼打法，用来总结规律；
4. 第三把叫“溯因”：看到异常结果倒推最可能的原因，查故障全靠它，但猜完必须验一下！

### 场景 3｜03 推理场景匹配对比（`SceneCompare`）
- ❌ **用错推理**：“我上周试了 2 个标题点击高，这就是爆款万能公式！”（把小样本归纳当成了 100% 演绎定律）
- ✅ **精准用对**：“用归纳提炼 3 个高点击特征，再用 A/B 验证；查故障先做溯因列 3 个疑似点，逐一排查。”

**口播字幕**：
1. 看对比：左边拿两个样本归纳出来的经验，当成百分百定律到处套，迟早翻车；
2. 右边各司其职：定规则用演绎，做总结用归纳，查问题先溯因再验证，思路稳如老狗！

### 场景 4｜04 3 秒随堂小测 & 口诀（`SceneQuiz`）
- **题目**：“公司规定超过 5000 元的采购必须总监签字，这笔采购 8000 元，所以必须找总监签。”——这是哪种推理？
- **答案**：**演绎推理**！从一般规则（>5000 须签字）推到具体案例（8000 元），结论 100% 必然成立。
- **金句口诀**：**定规用演绎，复盘靠归纳，查错先溯因再验证！**

**口播字幕**：
1. 三秒自测：规定五千元以上要签字，这笔八千元所以要签字，属于哪种推理？
2. 对，这就是演绎推理，从规则推到具体个案，百分百确定！
3. 记住口诀：定规用演绎，复盘靠归纳，查错先溯因再验证！
