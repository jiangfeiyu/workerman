# EP15｜述职答辩与面试：怎么证明“成果真是你做出来的”？（STAR 因果链升级）

> **本集学习目标**：告别“我负责了 A，后来涨了 B”的弱关联述职，用逻辑学中的**排他性因果链**升级 STAR 法则。

---

## 一、 自己先学懂（1 分钟内核 + 职场自测）

### 核心概念
很多人用 STAR（情境-任务-行动-结果）讲项目，依然被面试官/评委怼“这功劳真是你的吗？”因为 **Action 和 Result 之间缺少因果证明**：
- **普通 STAR**：接手了活动页（S/T） ➔ 优化了文案和弹窗（A） ➔ 转化率涨了 15%（R）。（容易被质疑：是不是刚好赶上大促？）
- **因果链升级版**：加一步 **归因验证（排除了大盘与他人动作）** + **方法论沉淀（可复用）**，证明“**如果没有我的动作 A，结果 R 不会发生这么大**”。

### 随堂自测
> 面试官问：“你刚说重构后接口快了 50%，怎么证明是你的重构代码带来的，而不是运维刚好加了两台服务器？”

**答案解析**：如果答不上来，说明 Action 和 Result 之间只是时间先后（相关），不是因果！回答必须拿出**同配置压测对比数据**（同机房同机器下，重构前 200ms ➔ 重构后 95ms）。

## 二、 4 段式分镜与口播逐字稿

### 场景 1｜01 述职答辩翻车现场（`SceneHook`）
- **候选人**：我负责了改版项目，上线后核心转化率提升了 20%！
- **面试官**：那段时间市场部也在投广告，你怎么证明这 20% 是你改出来的？

**口播字幕**：
1. 述职答辩或面试时，最怕被评委问住这一句：
2. “你说业绩涨了百分之二十，怎么证明是你干出来的，而不是大盘涨的？”
3. 很多人背了 STAR 法则还是被问倒，就因为中间少了一根因果锁链！

### 场景 2｜02 图解 STAR 因果链升级（`ScenePractice` `mode="star-causal"`）
**口播字幕**：
1. 来看逻辑升级版 STAR 模型，关键就在 Action 和 Result 中间那一步。
2. 普通写法只是按时间顺序列出“我做了 A、结果出了 B”；
3. 升级写法必须加上“因果排他证据”：通过 A/B 对照、同机器压测或漏斗拆解，
4. 证明“去掉我的动作，这个成果就不会发生”，这才叫真正属于你的战功！

### 场景 3｜03 述职表达前后对比（`SceneCompare`）
- ❌ **弱因果流水账**：“我主导了首页改版和文案优化，上线一个月后下单量提升 20%。”
- ✅ **硬核因果证明**：“锁定旧版跳出率 62% 的卡点，做分步引导改版；经 14 天 A/B 对照剔除投放波动后，实验组转化净提升 11.4%。”

**口播字幕**：
1. 看对比：左边说了“主导”“优化”，数字看着吓人，经不起深挖；
2. 右边精准交代痛点、动作和对照净值，哪怕数字从二十降到十一点四，含金量反而翻倍！

### 场景 4｜04 3 秒随堂小测 & 口诀（`SceneQuiz`）
- **题目**：“我接手团队后建立了周会制度，半年后团队离职率从 15% 降到了 5%，说明周会很有效。”——哪里有因果漏洞？
- **答案**：忽略了同期混杂因素（例如半年后刚好普调了薪资、或行业大环境变冷大家不敢跳槽），仅靠时间先后推不出因果。
- **金句口诀**：**先做后成不叫因，对照排除才服人！**

**口播字幕**：
1. 三秒自测：建了周会制度后离职率下降，能直接算成周会的功劳吗？
2. 不能！可能同期涨薪了或大环境变冷，没做排除不能归因。
3. 记住口诀：先做后成不叫因，对照排除才服人！
