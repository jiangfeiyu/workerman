【Linux 架构内功】为什么操作系统严禁应用程序（如 PHP、Python、Nginx）直接操作显卡、物理内存条等硬件？如何进行权限划分？	<b>1. 根本原因</b>：<br>防止程序意外或恶意覆盖物理内存、越权窥探其他进程数据（如微信记录或银行密码）或损坏硬件设备。<br><br><b>2. 权限划分</b>：<br>• <b>用户态（User Space）</b>：普通程序运行的受限安全房间，绝对禁止直接触碰硬件和执行特权指令；<br>• <b>内核态（Kernel Space）</b>：操作系统内核独占的特权区域，全权管理所有硬件资源（CPU 调度、显卡、网卡、物理内存分配）。	Linux基础 内核架构 用户态与内核态 Chapter00
【Linux 架构内功】什么是“系统调用（System Call，简称 Syscall）”？为什么 PHP 的 <code>echo &quot;Hello\n&quot;;</code> 本身根本不会点亮显示器？	<b>1. 系统调用的本质</b>：<br>系统调用是<b>用户态程序请求内核代为执行特权操作的受控入口（API / 办事申请单）</b>。<br><br><b>2. echo 的底层真相</b>：<br>用户态的 PHP 没有任何权限直接操作显卡硬件。当执行 <code>echo</code> 时，PHP 只是在向内核递交一张叫 <code>write</code> 的申请表（触发系统调用切入内核态），由内核保安代为将字符推向终端屏幕并点亮像素。	Linux基础 系统调用 Syscall echo write Chapter00
【Linux 性能内功】为什么纯算术计算（如 <code>$a = 1 + 1;</code> 或 10,000 次 for 循环累加）不会触发任何系统调用？	<b>1. 计算位置</b>：<br>纯算术计算是在当前分配给进程的 <b>CPU 通用算术寄存器（如 RAX/RBX）</b> 与进程自身私有内存中完成的。<br><br><b>2. 为什么不用找内核</b>：<br>CPU 寄存器是进程私有的“草稿纸”，即使算错也绝不会伤害其他进程或破坏系统硬件；<br><br><b>3. 性能收益</b>：<br>避免了从用户态切换到内核态的高昂特权级上下文切换（Context Switch）开销，执行速度极快（纳秒级）。	Linux性能 CPU寄存器 系统调用开销 Chapter00
【Linux 调试神器】如何用 <code>strace</code> 命令透视 PHP 脚本底层的系统调用？如何仅过滤追踪指定的系统调用（如 write 和 nanosleep）？	<b>1. 基本透视命令</b>：<br><code>strace php script.php</code><br><br><b>2. 过滤特定系统调用（强烈推荐，避免噪音）</b>：<br><code>strace -e trace=write,clock_nanosleep php script.php</code><br><br><b>3. 作用</b>：<br>能够抓捕进程向 Linux 内核递交的一切“办事申请表”，是底层性能分析与疑难排障的第一神器。	Linux命令 调试排障 strace Chapter00
【Linux 底层拆解】解读在 <code>strace</code> 中捕获的系统调用：<br><code>write(1, &quot;Hello Linux!\n&quot;, 13) = 13</code> 各参数与返回值代表什么？	• <code>write(...)</code>：Linux 内核提供的写文件/管道/设备系统调用接口；<br>• <code>1</code>：目标文件描述符 FD（1 号代表标准输出 <code>STDOUT</code>，默认指向当前终端屏幕）；<br>• <code>&quot;Hello Linux!\n&quot;</code>：待写入的实际字符数据；<br>• <code>13</code>：请求写入的字节长度（包含末尾的换行符 <code>\n</code>）；<br>• <code>= 13</code>：内核返回结果，表示成功写入了 13 个字节。	Linux底层 系统调用 write 文件描述符 Chapter00
【操作系统生命周期】硬盘上的静态代码文件（Program）与内存中的活体进程（Process）有何本质区别？	<b>1. 程序（Program）</b>：<br>躺在硬盘上的静态二进制文件或脚本文本，是“施工图纸”，不消耗 CPU 与内存，没有生命周期；<br><br><b>2. 进程（Process）</b>：<br>被操作系统加载进内存中、被分配了独立 PID、内存地址空间、文件描述符表等资源的“活体执行打工人”；<br><br><b>3. 现象</b>：<br>如果脚本几毫秒就执行完毕退出，进程即被内核销毁，在 <code>ps</code> 列表中将瞬间找不到。	Linux概念 进程与程序 生命周期 Chapter00
【Linux 调度内功】正在执行 <code>sleep(60);</code> 的进程会消耗 CPU 算力吗？为什么？在 <code>ps aux</code> 中其状态（STAT）是什么？	<b>1. CPU 占用率</b>：<br><b>0.0%</b>，完全不消耗任何 CPU 算力。<br><br><b>2. 内核行为</b>：<br>调用 <code>clock_nanosleep</code> 后，内核将该进程移出 CPU 调度队列，放入<b>睡眠等待队列（Wait Queue）</b>挂起，直至定时器到期才重新调度唤醒；<br><br><b>3. 状态标识（STAT 列）</b>：<br>显示为 <b><code>S</code>（Sleeping，可中断睡眠态）</b>，而非 <code>R</code>（Running，正在运行或就绪运行）。	Linux调度 sleep 进程状态 ps Chapter00
【Linux 进程管理】如果同时在终端运行 3 个一模一样的 <code>php worker.php</code>，内核保安如何区分它们？	<b>机制</b>：<br>通过分配全系统唯一的正整数身份证号 —— <b>PID（Process ID，进程标识符）</b>。<br><br><b>作用</b>：<br>即使多个进程的命令名、源代码、执行用户完全一致，内核调度器、信号机制（如 <code>kill -9 $PID</code>）以及运维人员均依靠唯一的 PID 进行精准控制与跟踪。	Linux基础 进程管理 PID Chapter00
